# 声誉、徽章、悬赏与通知规则

> 负责人：PO    最后更新：2026-10-10
> 说明：本文档是**唯一业务规则来源**，Sprint Review 验收时逐条对数。
> 标注「待确认」的条目必须在对应 Sprint Planning 前找教师 / 助教确认，确认后删除标记。

## 1. 声誉值规则（来源：教学方案 2.3.3）

| 行为 | 分值 | 待确认项 | 确认结果 |
| --- | --- | --- | --- |
| 回答被采纳 | +15 | 取消采纳 / 更换采纳时是否回滚？ | 待确认 |
| 回答被赞 | +10 | 同一用户重复点赞如何处理（幂等）？ | 待确认 |
| 回答被踩 | −2 | 是否设置声誉下限（不允许为负）？ | 待确认 |
| 提问被踩 | 待确认 | 提问是否参与声誉计算？ | 待确认 |
| 撤销投票 | 待确认 | 撤销点赞是否扣回 +10？ | 待确认 |

**验收要求**
1. 上述分值在代码中必须有**唯一来源**（不得散落硬编码）；
2. 声誉变更必须可通过个人主页观察到；
3. 声誉变更应产生一条领域事件（供通知子域消费）。

## 2. 徽章规则

| 徽章 | 获得条件 | 待确认项 |
| --- | --- | --- |
| 回答数徽章 | 累计回答数达到阈值 | 阈值是多少（10 / 50 / 100）？ |
| 采纳率徽章 | 采纳率 ≥ 阈值且回答数 ≥ 最小值 | 阈值是多少？样本量下限？ |
| 连续活跃徽章 | 连续活跃天数达到阈值 | 天数阈值？"活跃"如何定义（登录 / 发帖 / 投票）？ |

## 3. 教师悬赏规则

| 项 | 内容 | 状态 |
| --- | --- | --- |
| 积分来源 | 教师账号的积分池 | 待确认：无限额 / 学期配额 |
| 单题悬赏上限 | — | 待确认 |
| 结算时机 | 采纳时 / 到期时 / 手动发放 | 待确认 |
| 未产生满意答案 | 悬赏是否退回教师 | 待确认 |

## 4. 通知规则

| 事件 | 是否通知 | 通知对象 | 待确认项 |
| --- | --- | --- | --- |
| 我的问题被回答 | 是 | 提问者 | — |
| 我的回答被采纳 | 是 | 回答者 | — |
| 我被 @ | 是 | 被 @ 用户 | — |
| 我的问题被编辑 | 待确认 | 回答者 | 是否需要？ |

**强约束（已确认）**：通知发送失败**不得阻断主流程**。例如采纳成功但通知发送失败，采纳仍必须成功，通知进入重试或记日志。
